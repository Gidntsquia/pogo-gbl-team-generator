- **What changed (`src/engine/parallel.js`):** `createExecutor` no longer dispatches specs to whichever worker asks first off a shared `nextIndex` cursor (availability-based; timing-dependent). New exported `partitionContiguous(n, workers)` splits `[0, n)` into `workers` as-even-as-possible contiguous ranges, computed once per `run()` call purely from `specs.length` and the pool's (fixed-at-boot) thread count; each worker only ever pulls its next spec from inside its own range (tracked via a per-worker `active.cursor[workerIndex]` instead of one shared cursor). `runBattles()`'s signature/behavior/return-shape are unchanged (still create→run→close). Chose contiguous over striped/round-robin: callers' flat spec lists already group a matchup's battles adjacently (all 9 lead pairings of one candidate-vs-meta-team pair, etc.), so contiguous chunks keep that locality inside one worker's per-spec build cache instead of spreading it thin — full rationale in the module header and `src/engine/README.md`'s new "Deterministic spec → worker partitioning" section.
- **Why this matters (not just refactoring):** each worker keeps its own per-spec Pokemon-instance build cache and reuses instances across the specs it personally handles; reusing an instance across sequential battles has pvpoke's own known order-sensitivity (T15b/T15c's "Known limitation", T20/T20b's mechanisms 1/2). Under availability-based dispatch, which worker got which spec depended on real wall-clock timing, so two runs of the identical `(specs, threads)` could assign specs to workers differently — meaning even a config that's supposed to be fully reproducible (fixed seed, fixed thread count) wasn't guaranteed to replay bit-for-bit. Deterministic partitioning makes worker assignment itself a pure function of `(specs.length, threads)`, closing that gap — the actual "REPRODUCIBLE bit-for-bit at fixed (seed, threads)" bar T21's determinism-investigation-derived requirement asks for. (Serial↔threaded divergence on ~0.28% knife-edge battles is still open — that's T20b's mechanism 2, untouched by this fire, as GOALS says it should be.)
